fix(str): align classify and case predicates to UCD 16.0.0 (CPython 3.14)

str.isalpha(), str.isalnum(), str.isdecimal(), str.isdigit(),
str.isnumeric(), str.isspace(), str.isprintable(), str.islower(),
str.isupper(), str.istitle() now use the 16.0.0 UCD tables instead of
ICU 17.0 lookups. This means these predicates correctly return False for
the ~93 characters that were added in Unicode 17.0 but are unassigned
in 16.0.0 (matching CPython 3.14 behavior).

Changes:
- classify.rs: replace ICU GeneralCategory::for_char, NumericType::for_char,
  BidiClass::for_char with the 16.0.0 tables (GENERAL_CATEGORY_LATEST,
  NUMERIC_TYPE_LATEST, BIDI_CLASS_LATEST).
- case.rs: replace ICU Lowercase/Uppercase/Cased/Case_Ignorable binary
  property lookups with the 16.0.0 DerivedCoreProperties tables.
- data.rs: add lookup_range(), category_of(), make DecompositionType
  pub(crate) for the generated DECOMP table.
- build.rs: add DerivedCoreProperties.txt parsing for LOWERCASE_PROP,
  UPPERCASE_PROP, CASED_PROP, CASE_IGNORABLE_PROP tables; fix BOM
  handling in parse_unicode_3_2; make generated tables pub(crate).

Note: str.lower()/str.upper()/str.title() still use Rust std's
case mappings (ICU 17.0), so the method_checksum expectedFailure
remains for the 4 characters where 17.0 assigns case mappings
(A7CE/A7CF/A7D2/A7D4). The predicates are now correct.
