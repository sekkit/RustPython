feat(capi): PyModuleDef/PyModule_Create + run C-API tests on Windows

- Add PyModuleDef/PyModuleDef_Slot/PyModuleDefBase with CPython-exact
  layouts, PyModuleDef_Init, PyModule_Create/_PyModule_Create, and the
  CPython 3.15 (PEP 793) PySlot machinery: PyModule_FromSlotsAndSpec,
  PyModule_Exec, PyModule_ExecDef, PyModule_SetDocString,
  PyModule_GetDict, PyModule_Check/CheckExact. Slot ids use the 3.15
  renumbering (Py_mod_create=84, Py_mod_exec=85, ...).
- Add PyType_GetSlot, PyType_Freeze and PyType_FromSlots (heap type
  creation via the vm's type machinery), PyErr_CheckSignals,
  PyUnicode_FromWideChar/PyUnicode_AsWideChar, and a minimal buffer
  protocol (PyObject_GetBuffer for bytes/bytearray, PyBuffer_Release,
  PyBuffer_GetPointer) - the 14 symbols pyo3 needs to link its tests.
- Vendor pyo3-ffi 0.29.2 (pyo3-ffi-patched) and drop its Windows
  `#[link(name = "pythonXY")]` fallback attribute: it made MSVC resolve
  every Py* symbol through an import library as __imp_* entries, which
  conflicts with rustpython-capi's own no_mangle exports and prevented
  `cargo test -p rustpython-capi` from linking on Windows at all
  (upstream CI skips these tests on Windows for this reason). Direct
  references now link against the rustpython-capi exports. Wire the
  patch into the workspace [patch.crates-io].
- Unit tests for PyModule_Create with a PyMethodDef table and for
  PyModuleDef_Init index assignment. Full `cargo test -p rustpython-capi
  --lib`: 103 passed, 0 failed on Windows.
