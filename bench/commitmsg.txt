fix(profile): c_call trace events only for builtin functions/methods; trace through specialized call instructions

profile.Profile's output differed from CPython's expected test_profile
output in three ways: extra ":0(C)"/":0(range)" entries (class/type calls
recorded as C calls), a 2/4 call count for list.append, and systematic
timing differences. Root causes, both in the VM:

1. PyCallable::invoke/invoke_vectorcall fired c_call/c_return/c_exception
   for EVERY non-Python-function callable, but CPython's trace_call_function
   (ceval.c) only fires them for PyCFunction/PyCMethod and for method
   descriptors (bound with the first argument); types, partials, etc. are
   called without tracing events. Now the trace argument is chosen by
   trace_c_callable(): builtin functions/methods pass through unchanged,
   method descriptors are bound with the first argument (skipped when there
   is none), everything else fires no C-call events.

2. The adaptive call specializations CallMethodDescriptorNoargs/O/Fast/
   FastWithKeywords, CallLen, CallIsinstance and CallListAppend invoked the
   native function directly, bypassing the trace machinery, so calls made
   after an instruction was specialized were invisible to the profiler
   (the 2/4 append count). While tracing is active they now fall back to
   the generic vectorcall path, matching CPython's behavior of using the
   un-specialized CALL while tracing (CallBuiltinO/Fast/FastWithKeywords,
   CallNonPyGeneral and CallKwNonPy already route through vectorcall and
   needed no change; type-call specializations CallType1/Str1/Tuple1/
   CallBuiltinClass/CallAllocAndEnterInit correctly fire no c_call, as in
   CPython).

Result: profile.Profile output is byte-identical to CPython 3.14's expected
output (do_profiling print_stats/print_callers/print_callees all match), so
the @unittest.expectedFailure on ProfileTest.test_cprofile is removed and
the CProfileTest wrapper in test_cprofile.py reverts to plain inheritance.
test_profile 7/7 and test_cprofile 24/24 green with zero expectedFailures.
