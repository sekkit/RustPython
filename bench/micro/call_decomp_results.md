# 调用分解（RustPython vs CPython 3.12，ns/op）

| 场景 | RustPython | CPython | 倍数 |
|---|---|---|---|
| A 纯调用 | 219.4 | 46.5 | 4.7x |
| B 局部别名调用 | 219.7 | 48.7 | 4.5x |
| C 闭包调用 | 211.2 | 46.1 | 4.6x |
| D 3参数调用 | 447.4 | 121.2 | 3.7x |
| E 变长参数调用 | 454.6 | 116.0 | 3.9x |
| F 全局名加载(无调用) | 87.4 | 30.6 | 2.9x |
| G 递归深度1 | 515.5 | 88.8 | 5.8x |

## 关键观察
- 纯调用地板：A=219ns，其中全局名解析 F=87ns；帧创建+分派 ≈132ns
- **参数打包成本**：D-A = 228ns（2 个额外参数 → 每参数 ~114ns），
  CPython 仅 D-A=75ns（每参数 ~37ns）→ RustPython 参数打包贵 ~3x
- 递归 G ≈ A×2 + 75ns 帧链接 → 两层帧成本 ~515ns，CPython 仅 89ns
- 结论：**fn_call 路径的 FuncArgs 堆分配/BMI 打包是明确可节流项**，
  与 vectorcall 直传（栈上参数数组 + 复用 FuncArgs）方向一致
